# サンプルから機能を追加する順序

このサンプルは新しいツールへコピーする完成品ではなく、変更箇所を辿る教材です。最初に[設計方針](../../../../設計書/12_サンプル・テンプレートツール設計方針.md)と[Common詳細設計](../../../../設計書/10_Common詳細設計.md)を確認します。新規ツールは`New-SalesSupportTool.ps1`でテンプレートから生成し、ToolId・業務仕様を個別に決めてください。

入力・計算は既定の`standalone`起動プロファイル（単独開発）でPortal・DBなしに確認できます。DB機能・ファイル処理・認証・ログを結合確認するときは`portal`プロファイルへ切り替え、開発用DBとPortalを使ってください。[設定手順](../../../config/README.md#ツールを単独で開発する)に沿って準備します。本人を特定できるのは、単独開発でもサイトの匿名モードでもない場合だけです。匿名モードの固定共通ユーザーはAspNetUsersに存在せず、本人向けデータの所有者に使えません。ユーザーを所有者とする新しい機能は`CommonOptions.HasIdentifiedUser`で判定し、falseのときは画面・サーバーの両方から利用を拒否してください。

## 開発サイクル

[リポジトリ指示](../../../../AGENTS.md#開発方針作業サイクル)に従い、次の順で進めます。開発中は後方互換・旧版からのデータ移行を行いません。

1. 要件・設計書・SQL仕様・画面モック・READMEを先に更新し、矛盾や古い情報を解消します。
2. 対応するテストを先に追加・修正し、意図した理由で失敗することを確認します。金額の丸め、日付基準、NULLの意味、拒否条件も扱います。
3. 必要な最小実装を行い、テストを通します。DB構造変更は初期構築SQLへ反映し、新しい空の開発DBで検証します。既存DBへ初期構築SQLを再実行しません。
4. 不要コード・不要テスト・資料矛盾を確認し、整理後に影響範囲の`dotnet build`・`dotnet test`を行います。SQL実行・実DB・Portal・IIS・Cookie往復は別の結合検証として記録し、未実施なら成功と書きません。

## 変更箇所と実装時の注意

- 入力項目を増やすときは`Models/EstimateModels.cs`に表示名・型・入力属性を追加し、`Views/Tool/Index.cshtml`に欄を置きます。`Services/EstimateService.cs`でサーバー側の範囲・選択肢を再検証します。画面属性だけで受理条件を決めないでください。
- 計算内容を変えるときは`EstimateService.CalculateAsync`と`EstimateResult`を変更し、画面結果とTSV出力の両方を揃えます。
- 永続化が必要なときだけ、ツール固有Entity・DbContext・Serviceを追加します。SQLの列・制約・索引とEFマッピングを揃え、Portal/Commonの表をツール側へ集約しません。共通監査5列を持つ表はEntityをCommonの`AuditedEntity`から派生させ、`ConfigureAuditColumns("表名", "dbo")`で対応付けます。監査列のマッピングは手書きしません。
- 更新時には本人の条件を常に付け、DB監査列`UpdateCount`の元の値で競合を検出します。副作用のあるPOSTにはCSRF、送信IDの一意制約、成功後のGETへの遷移を組み合わせます。ブラウザーのボタン無効化だけに依存しません。
- ファイルを使う場合はCommonの`IFileStorage`とDBの`TOOL`＋`TOOL_INPUT`条件を使い、一時ファイルを`finally`で破棄します。結果や入力ファイルを恒久保存しない設計を維持します。CSV/TSVはCommonの出力処理を使います。
- ControllerはHTTPと画面遷移、Serviceは業務判断に分けます。入口の`WEB_OPEN`（Commonの`WebOpenLoggingFilter`）、実行の`WEB_EXECUTE`（Commonの`IToolUsageLogger.WriteExecuteAsync`）、共通認可とCSRFを残します。例外時に成功ログを先に書かないでください。
- `WebOpenLoggingFilter`はツールの入口アクション1つだけへ適用します。ツール内で画面を増やしても、そのたびに`WEB_OPEN`を記録しません。記録単位は[ログ記録](../../../../設計書/02_画面・機能設計.md#logs-usage)に従います。
- 画面を追加するときは`IToolPageShell.Build("見出し")`で共通レイアウトの表示情報を作ります。ツール内に中間階層がある場合だけ、そのパンくずを追加で渡します。Portalのトップ・ツール一覧のパンくずは手書きしません。
